# Apple II 모킹보드 드라이버와 플레이어

소스는 `src/mb_apple2/`(드라이버와 파일 스트리머)와 `src/mb_basic/`(상주 플레이어 `MPLAY`, `& MPLAY` 명령)에 있습니다.
디스크 빌더는 `src/mb_disk/`에 있고, 완성된 디스크는 `src/dist/mb.dsk`입니다.

## 빠른 시작

```
src\converter\midi2mbf.bat song.mid                 ->  song.MBF, song.txt
src\tune\tune2mbf.bat "T120 CDEFG"                  ->  tune.MBF (텍스트 곡, TUNE_FORMAT.md 참고)
src\mb_disk\build_disk.bat out.dsk folder_or_files  ->  src\dist\out.dsk 에 부팅 가능한 DOS 3.3 디스크
```

`build_disk.bat`(cc65는 `C:\cc65`에 있어야 하며, 먼저 `src\mb_basic\build.bat`을 빌드하세요)는 `src\mb_disk\dos33blank.dsk`
(절대 바꾸지 않음)를 복사해서 `MPLAY`(플레이어), `CATALOG`에 보이는 보통 DOS 파일 `<제목>.MBF`로 된 각 곡,
Applesoft `HELLO` 메뉴, 텍스트로 쓴 곡을 연주하는 `DEMO` 프로그램, 파일 이름을 묻는 `PLAYMBF` 프로그램을 넣습니다.
모킹보드가 있는 Apple II+ / IIe(48K, DOS 3.3)에서 부팅하고 곡 번호를 고르세요. `--base other.dsk`를 주면 곡, `MPLAY`,
`PLAYMBF`를 새 디스크가 아니라 이미 있는 디스크(예: K-HANGEUL / KBASIC 디스크)에 넣습니다.

플레이어는 `MPLAY` 하나입니다. `BRUN MPLAY`가 Applesoft 명령 `& MPLAY "NAME"`을 설치하고(메뉴는 맨 처음에 이것을 합니다),
나머지는 모두 그것을 부르는 BASIC 프로그램입니다:

```
10 PRINT CHR$ (4);"BRUN MPLAY"
20 & MPLAY "HOTELCALIFORNIA.MBF"
```

곡이 나오는 동안 아무 키나 누르면 멈춥니다. `& MPLAY "NAME",1`은 곡이 끝나면 다시 시작하고, `,2`는 키를 효과음으로 바꿉니다
(ESC나 Q는 멈춤). 이 명령은 `TUNE_FORMAT.md`에 설명되어 있습니다. 메모리 사용량, 그리고 한글 디스크에서 다른 `&` 명령이 피해야 할 것은
`ADDON_MEMORY.md`에 있습니다.

## 다른 프로젝트의 디스크에서 `MPLAY` 쓰기

`src\mb_basic\build.bat`은 완성된 플레이어를 `src\dist\MPLAY.bin`(그리고 레이블 파일 `MPLAY.lbl`)으로 복사합니다. 그래서 다른 프로젝트는
아무것도 빌드하지 않고 거기서 가져다 쓸 수 있습니다:

- `MPLAY.bin`은 3,268바이트의 순수 바이너리이며 **`$7D00`**에 로드해야 합니다. DOS 3.3 디스크에 그 주소를 가진 **B** 파일 `MPLAY`로 넣으세요.
  예: `cmd /c "C:\bin\acx.exe -p disk.dsk MPLAY B 0x7D00 < MPLAY.bin"`.
- `BRUN MPLAY`는 `$7D00`에서 실행됩니다(설치 루틴이 첫 바이트이며, `MPLAY.lbl`의 `install`이 `$7D00`입니다). `HIMEM`을 `$6900`으로 낮추고
  `& MPLAY`를 설치합니다. 쓰는 것은 모두 `$6900-$89FF` 안에 있습니다(K-HANGEUL, KBASIC, 다른 `&` 명령과 나란히 놓일 때의 의미와
  설치 순서는 `ADDON_MEMORY.md` 참고).
- 곡은 같은 디스크에 섹터가 스트리밍 순서로 놓인 DOS **T** 파일로 넣습니다. `src\mb_disk\build_disk.py --base other.dsk`가 이것을 하며,
  그 코드가 기준입니다.
- `mb_basic`, `mb_apple2`, `mb_layout.inc`가 바뀌면 `MPLAY.bin`(그리고 `dist\`)을 다시 빌드하세요.

## 곡을 저장하는 방식

각 곡은 보통의 DOS 3.3 텍스트(T) 파일입니다(`CATALOG`에 보이고, `BLOAD`는 거부합니다). `build_disk.py`가 디스크 이미지에 바로 써 넣는데,
섹터를 일부러 배치하기 때문입니다. 각 트랙에서 0,14,13,...,8,7,6,...,1,15 순서로 놓으면(드라이브가 물리 섹터 0,2,...,14,1,3,...,15 순으로 내보냄)
기다림이 가장 적습니다. `MPLAY`는 카탈로그에서 파일을 이름으로 찾고, 파일의 트랙/섹터 목록과 섹터를 DOS 자신의 `RWTS` 루틴으로
앞에서부터 한 번에 4섹터 단위로 읽습니다. 그래서 곡은 디스크만큼 클 수 있습니다. DOS가 파일을 읽는 속도는 약 1.3 KB/s밖에 안 되고
`BLOAD`에는 오프셋이나 길이가 없어서, `MPLAY`는 DOS로 읽지 않습니다. 바이너리(B) 파일도 되며, 4바이트 헤더는 건너뜁니다.

링은 1 KB 슬롯 4개입니다. 음악이 시작되기 전에 처음 슬롯 네 개를 읽으므로, 4 KB 이하의 곡은 한 번 읽고 나면 디스크를 다시 건드리지 않습니다.
더 큰 곡은 스트리밍합니다. 음악이 한 슬롯을 지나가면 드라이브를 켜고, 드라이브가 돌아가는 동안 음악을 64틱(1.3초) 더 연주한 다음, 다음 4섹터를
읽습니다(그동안 음악이 멈춥니다. 0.1~0.4초). 그리고 음악이 이어집니다. 테스트 곡 다섯 개(`mbf_out\`의 파일)는 디스크의 143,360바이트 중
129,792바이트를 씁니다.

## `.MBF` 파일 형식

8바이트 헤더(`MBF1`, 틱 속도 u16 리틀 엔디언, 반복 플래그, 예약)와, 틱마다 프레임 하나가 이어집니다:

- 개수 바이트 N(0~22)과 N개의 `[chip<<4 | register, value]` 쌍. 레지스터는 0~10(음높이, 노이즈 주기, 믹서, 음량)입니다.
  개수 0은 바뀐 것이 없는 틱입니다.
- 개수 바이트 `$80 + n`(n = 1~126)은 그런 빈 틱이 n번 연속된다는 뜻입니다. 곡의 대부분이 빈 틱이라 파일 크기가 절반으로 줄어듭니다.
- `$FF`는 스트림의 끝입니다. 첫 프레임은 전체 키프레임입니다.

이 형식은 변환기가 쓰고, `win_player.py`와 드라이버가 읽습니다. 타악기는 AY 노이즈 발생기로 연주합니다. 드럼 한 번은 몇 틱 동안 성부 하나를
차지합니다(변환기가 그 채널의 톤을 끄고 믹서에서 노이즈를 켜고, 칩의 노이즈 주기를 정하고, 음량을 줄여 갑니다).

## 게임에서 드라이버 쓰기 (`mb_driver.s`)

`mb_driver.o`를 링크하고 다음을 부릅니다:

| 루틴 | 입력 | 출력 |
| --- | --- | --- |
| `MB_INIT` | A = 슬롯 1~7, 또는 0이면 슬롯 4,5,6,7,2,1,3 순으로 찾음 | C 해제, A = 슬롯. C 설정 = 카드 없음 |
| `MB_PLAY` | A/X = 메모리에 있는 `.MBF` 파일의 주소 | C 설정 = 올바른 MBF1 파일이 아님 |
| `MB_POLL` | 없음. 자주 부를 것 | C 해제 = 연주 중, C 설정 = 멈춤 |
| `MB_UPDATE` | 없음. 틱마다 직접 한 번씩 부름 | C 해제 = 연주 중, C 설정 = 멈춤 |
| `MB_STOP` | 없음 | 두 칩을 모두 조용하게 함 |
| `MB_SFX` | A/X = 효과음 스트림의 주소 | 효과음이 `MB_UPDATE` 안에서 연주됨 |

다른 무언가가 다시 채우는 링 버퍼에서 읽는 곡(`mb_stream.s`가 이렇게 합니다)을 위해서는: `MB_RING`(읽기 포인터를 상위 바이트에서 되돌림),
`MB_POS`(읽기 포인터의 상위 바이트), `MB_TICK`(연주한 틱 수, 256 모듈로), `MB_PAUSE`와 `MB_RESUME`(디스크를 읽는 동안 칩을 조용하게 했다가
음량을 되돌리고 틱 타이머를 다시 시작)가 있습니다.

- `MB_POLL`은 6522 타이머 1(파일의 틱 속도로 설정됨)을 지켜보다가 타이머가 끝나면 `MB_UPDATE`를 실행합니다. 루프가 한 틱보다 느리면
  틱을 잃고 음악이 느려집니다. 정확한 타이밍이 필요하면 대신 자기 타이머에서 `MB_UPDATE`를 쓰세요.
- 제로 페이지: `$FA-$FE` 5바이트. 변수: 54바이트(세그먼트 `BSS`). 코드와 표: 972바이트.
- 효과음은 곡 프레임과 같은 형식의 스트림입니다(개수 바이트, `[chip<<4 | register, value]` 쌍, 끝은 `$FF`). 칩 1의 채널 B와 C
  (레지스터 2~5, 9, 10)를 빌려 쓰며, 그동안 음악이 거기에 쓰는 것은 보류되고 효과음이 끝나면 채널을 돌려줍니다. 다른 레지스터에 쓰는 것은
  무시됩니다. 톤만 있고 노이즈는 없습니다.
- 틱 속도는 16~255 Hz여야 합니다(`converter.py --rate`). 기본은 50 Hz입니다.

`mb_stream.s`(메모리에 DOS 3.3이 있어야 함. 링의 위치와 크기는 `mb_layout.inc`에 있음): `FILE_OPEN`(A/X = 파일 이름, Y = 길이.
건너뛸 헤더 바이트 수 0 또는 4를 돌려줌), `STREAM_OPEN`과 `STREAM_SERVICE`(링을 채움. 메인 루프에서 부름), `STREAM_STOP`(드라이브 모터 끔),
`STREAM_RESTART`(아래). DOS의 매개변수 목록은 `LOCRPL`(`$03E3`)로 찾고 `RWTS`(`$03D9`)로 읽습니다.

**스트리밍하는 곡을 반복하기.** 드라이버 자체의 반복 플래그는 곡 전체가 RAM에 있을 때만 동작합니다. `MB_POLL`이 스트리밍 곡이 끝났다고 알리면
`STREAM_RESTART`를 부르세요. 파일 처음부터 링을 다시 채우고 곡을 다시 시작합니다(C 설정 = 디스크 오류). 네 슬롯을 읽는 동안, 드라이브가
돌아가는 시간 말고도 약 0.5초 동안 음악이 멈춥니다. `& MPLAY "NAME",1`이 이렇게 합니다.

## `MPLAY`의 메모리 맵

`BRUN MPLAY`는 파일을 `$7D00`에 로드하고 `HIMEM`을 `$6900`으로 낮춥니다. 쓰는 것은 모두 `$6900-$89FF` 안에 있습니다.

| 범위 | 용도 |
| --- | --- |
| `$6900-$78FF` | 곡 링: 1 KB 슬롯 4개. 텍스트 곡도 여기에 컴파일됩니다(최대 3,840바이트) |
| `$7900-$793F` | 링 처음 64바이트의 복사본. 프레임이 링 끝을 넘어갈 수 있게 합니다 |
| `$7A00-$7AFF` | 카탈로그와 트랙/섹터 목록용 섹터 버퍼 |
| `$7B00-$7CFF` | 드라이버, 스트리머, 곡 컴파일러 변수 |
| `$7D00-$89FF` | 코드와 표 (파일의 3,253바이트) |
| `$06-$09`, `$EB-$EF`, `$FA-$FE` | 제로 페이지 (호출이 실행되는 동안) |
| `$03F5` | `&` 벡터 |

`$8A00` 아래에서 끝나므로 KBASIC(`$8A00-$93FF`), `TYPE`(`$8E00`), 한글 드라이버(`$4000` 아래 전부와 `$9400` 위 전부)와 나란히 그대로
돌아갑니다. 전체 맵과 규칙은 `ADDON_MEMORY.md`에 있습니다. 일반 DOS 3.3 디스크에서도 똑같이 동작합니다. 거기서는 `HIMEM`이 `$9600`이고,
`BRUN MPLAY`가 그것을 `$6900`으로 낮춥니다.

## 한계와 하지 않은 것

- **스테레오: 칩 1이 왼쪽 채널, 칩 2가 오른쪽 채널입니다.** 음의 절반이 안 들리면 스피커나 헤드폰의 양쪽과 윈도우 소리 균형이 동작하는지
  확인하세요. AppleWin에서는 윈도우 소리 설정을 고치기 전까지 칩 2의 음이 들리지 않았습니다. 채널마다 음 하나씩(칩 1 A, B, C, 그다음 칩 2 A, B, C)
  있는 테스트 디스크로 빠르게 찾을 수 있습니다.
- **AppleWin 1.32에서 들어 본 것은 음 하나, 6채널 음계, 로드한 곡뿐입니다** (슬롯 4의 모킹보드 C. 이전 플레이어로). 스트리밍하는 `MPLAY`는
  들어 보지 않았습니다. 실제 모킹보드나 실제 Disk II에서는 아무것도 돌려 보지 않았습니다. 섹터 순서와 읽는 시간은 MAME의 디스크 에뮬레이션에서
  나온 것이고, 1.3초의 회전 대기 여유는 실제 드라이브에 대한 추측입니다.
- **스트리밍하는 동안 음악이 멈춥니다.** 섹터를 읽는 시간만큼입니다. 기본 DOS 3.3 디스크 읽기는 CPU를 멈추기 때문입니다.
  Hotel California(43 KB)는 39번, 한 번에 0.2~0.4초씩, 약 10초마다 멈춥니다. 더 빽빽한 곡은 더 자주 멈춥니다. 부드럽게 스트리밍하려면
  인터럽트로 틱을 돌리는 전용 디스크 리더가 필요한데, 만들지 않았습니다.
- **링이 작습니다** (4 KB). 한글 디스크에서 BASIC에 메모리를 남기기 위해서입니다. KBASIC과 `MPLAY`가 올라가면 10,495바이트가 남습니다.
  슬롯이 더 많거나 크면 멈춤이 줄어듭니다. `mb_layout.inc`와 `mb_basic.cfg`를 바꾸세요.
- 메모리에 표준 DOS 3.3이 필요합니다 (`RWTS`는 `$03D9`, 매개변수 목록은 `$03E3`부터).
- **타이밍.** 드라이버는 1,022,727 Hz 클록을 가정합니다 (PRD, MAME과 같음). MAME에서는 틱이 22.5 ppm 느린 채로 일정합니다
  (206초에 4.6 ms). 실제 NTSC Apple II는 평균 약 1,020,484 Hz이므로 템포와 음높이가 약 0.2% 낮아질 텐데, 측정하지는 않았습니다.
- **인터럽트가 아니라 폴링입니다.** PRD는 IRQ 타이머를 허용하지만 폴링만 만들었습니다.
- 두 6522(`$Cn00`과 `$Cn80`)가 모두 응답해야 합니다. AY가 하나뿐인 카드는 감지하지 못합니다.
- **드럼은 근사치입니다.** (`--no-drums`는 드럼을 뺍니다.) 칩마다 노이즈 주기를 하나만 공유하고 엔벨로프가 없는 노이즈 발생기를 쓰며,
  여섯 성부가 모두 바쁘면 한 번 칠 때 몇 틱 동안 멜로디에서 성부 하나를 가져옵니다 (Hotel California는 드럼 1,258번 중 8번과 멜로디 음 870개를
  여섯 성부 제한 때문에 잃습니다).
- `& MPLAY`는 곡이 나오는 동안 프로그램을 멈춥니다 (`TUNE_FORMAT.md` 참고).
